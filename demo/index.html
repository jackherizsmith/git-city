A git repository, as a city

Git City

Every file is a building and every package is a district. The city grows and shrinks month by month from the real git history. Press Play, drag to orbit (shift-drag to pan), scroll to zoom, and hover any building to see its file.

Zoning code

A file's path and type decide what kind of building it becomes. The size of its plot comes from the largest the file ever grew, so plots stay put while the buildings on them rise and fall. Height comes from the file's current line count.

How the city runs

Population
Lines of code. A district's population is its package's size.
Districts and streets
Packages are districts, top-level folders are blocks and sub-folders are streets. Wider roads separate higher levels of the folder tree.
Metro
Packages that others import are interchanges, each with its own coloured line. A line runs to every package that imports from it, with more trains where there are more imports.
Traffic
Cars on a district's streets are that month's commits touching it.
Cranes
Files created this month. The biggest new buildings get one.
Rubble
Files deleted in the last two months.
Fires
Buildings touched by a fix commit this month glow and flicker.
Lit windows
Recent activity. A building touched this month is fully lit; the lights go out over the following months.
Derelict
Untouched for two years: greyed out, with dark windows.
Factories and smoke
Test files. Chimneys smoke when tests changed this month.
Waterworks
SQL files and migrations are storage tanks, usually down by the water.
Airport
Each release that month (a tag, or a merge matching your release pattern) is a flight taking off.
Helicopters
Commits mentioning a hotfix, circling the district with the most fixes.
Port
Optional business metrics: ships, containers and visitors per month, from a metrics file.
City news
Fixed rules, no AI: new districts, demolitions, the biggest commits by name, population milestones, rush hours, fire storms and metric records.

    How it is made

    git_city.py walks git log --numstat --summary -M once, following renames and deletions, so every file has a month-by-month line count and a list of the months it was touched and fixed. It zones each path, lays the folder tree out as a squarified treemap with street gaps, and counts imports between workspace packages for the metro.

    Plots are sized from the largest each file ever grew, so they stay put over time. Height grows with the square root of lines, so the biggest files read as towers without dwarfing the rest. Metro lines use the imports at the latest commit.
